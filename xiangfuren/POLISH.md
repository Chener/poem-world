# 固定打磨 prompt（循环中不改）

本文件在整个打磨循环里保持不变。每一轮新开一个会话，读它，做一件事。

## 循环机制：Ralph

这一首用**纯 Ralph**，不再有独立 critic 盲比（第一段的 10 轮用的是 Gauntlet 式 critic +
Ralph 式一轮一事的混合；船长 2026-09-17 裁定：一首只用一种机制，混合的效果不好）。

每一轮：

1. 读 `PRD.md` 和 `progress.txt`。
2. 从 `PRD.md` 的「待办」里挑**最上面那一条还没划掉的**。只做这一条。
   不重写整个世界，不做无关的顺手优化。
3. 做完自己验证：`./shoot.sh <round>` 拍 3 个定机位，逐张看，对着 `PRD.md`
   的「意象对照表」和「人迹的规矩」过一遍自检清单，写下结论。
4. 把 `index.html` 快照到 `versions/<round>/index.html`，
   用 `shared/logrow.py` 往 `log.jsonl` 追一行，`progress.txt` 追一行完成信号，
   `PRD.md` 里把那条划掉。提交。

自检清单（每轮都要回答，写进 `progress.txt`）：

- 这一条待办在截图里看得见吗？看不见就等于没做。
- 有没有在画面里引入人形？（不允许）
- 三个机位里，「等而不得」还压得住「风景好看」吗？
- 有没有碰 `xiangfuren/` 以外的文件？（不允许）

## 约束

零依赖，浏览器直接打开 `index.html` 就能跑；不引入 npm 构建、不引入 CDN 运行时依赖；
左侧是可漫游世界（WASD + 鼠标 + 触控），右侧是可折叠时间线（读 `log.jsonl`）。

## 人迹：只用物件，不做人形

见 `PRD.md`「人迹的规矩」。这个世界里不出现人形；人只通过衣裳、罾、水中之室、
席案、灯在场。做不好宁可不做。

## 截图（白天的资源规矩，船长 2026-09-17）

3 机位、960×600、`?shot=1`（无字幕、无标题、无罗盘）。
每帧一个 `chrome-headless-shell` 一次性进程，`nice -n 15`，
`perl alarm` 90 秒硬超时，`--virtual-time-budget=5000`，写完文件就退出；
三个世界共用 `mkdir` 锁 `/tmp/poem-world-shot.lock`。
每轮开工前自查：一分钟 load < 6 且内存空闲 > 40%，不满足等 60 秒再看。不开可见窗口。
全部在 `./shoot.sh` 里，不要另起一套。

## 硬性要求

页脚必须标注：loop 机制（Ralph）、harness（Claude Code）、模型（Opus 5，非 fast）、
推理强度（medium）、轮数与停止原因。

## 走出机位

三个定机位是验收用的，不是这个世界的全部。每隔几轮换一个没去过的地方站着看
（`?cam=x,z,yaw,pitch&shot=1` 就能拍任意机位，图放在 scratchpad，不进仓库）：
走到水中之室门前、走到席跟前、走到水上去看蛟、蹲到蘋中去看鸟。
第 37–50 轮里一多半的缺口是这么找出来的——只看那三张图，它们都发现不了。

## 停止条件

`PRD.md` 待办清空 / 自检连续两轮判「到位」/ 距 Claude 周限刷新不足 30 分钟。先到先停。
不设轮数上限。
